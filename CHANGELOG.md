# Changelog

## Unreleased

### Added

- `Concurrent::with_changeover_punishment` and `schedules::ChangeoverPunish` (`All(schedule)`, `Directional({(from, to): schedule})`): punishment of changeover responses. A changeover punisher receives a response only when the response confirms a changeover (the test that arms COD, so with FRCO the FRCO-th consecutive response on the new operandum); every other step is a time tick for it. `All` is one schedule shared by every direction; `Directional` keys must name two different operanda of the components. Punishers that fire on the same response (per-operandum `punish` and a changeover punisher) add their magnitudes. A response punished by a changeover punisher has `changeover_punished` in outcome meta. The spec of `Concurrent` takes `punish_changeover` (a schedule spec) or `punish_directional` (an array of `{"from", "to", "schedule"}`; a repeated pair is a `Config` error); giving both is a `Config` error, `null` is the same as absent. `tests/conformance.rs` replays the new fixtures `compound/concurrent_punish_changeover.json` and `compound/concurrent_punish_directional.json`.
- `MatchingToSample::with_correction` and `schedules::Correction` (`Disabled`, `Unlimited`, `Bounded(limit)` with `limit >= 1`): a baseline trial that ends incorrect (a wrong choice or a timeout) is presented again after the ITI, with the same correct operandum, trial type and comparison positions and no draw from the random stream; probe trials are not repeated. With correction active, outcome meta reports `correction_trial`. The spec of `MatchingToSample` takes `correction`: `{"mode": "disabled"}`, `{"mode": "unlimited"}` or `{"mode": "bounded", "limit": N}`; absent is disabled. `tests/conformance.rs` replays the new fixture `trial/mts_n2_seed7_correction1.json`.
- `schedules::Lag` and the spec type `"Lag"` (`n`, optional `length`, default 1): differential reinforcement of response variability (Page & Neuringer, 1985). A unit is `length` consecutive responses read as their operanda; units do not overlap; a unit is reinforced at its last response iff it differs from each of the previous `n` units (fewer while fewer have been emitted), and unreinforced units stay in the comparison list. `Lag 0` reinforces every unit; `n` and `length` go up to `u32::MAX` (`LAG_MAX`). `Schedule::state()` reports `current_unit` and `units_compared`. `SPEC_TYPES` has 37 entries. `tests/conformance.rs` replays the new fixture `differential/lag_2_length_2.json`.
- `opk_from_spec` (C), `Schedule.fromSpec` (WebAssembly), and `UniffiSchedule::from_spec` (Swift/Kotlin) build any schedule from a schedule spec given as a JSON string, through `spec::from_spec`. The per-schedule constructors are unchanged.
- `spec::from_spec`: `Concurrent` takes the optional `cod_directional` (an array of `{"from", "to", "cod"}`; a repeated pair is a `Config` error) and `punish` (an object of operandum to schedule spec), built with `Concurrent::with_extensions`.
- Python: `contingency_core.from_spec` and `Schedule.from_spec` build any schedule from a spec given as a dict or a JSON string; `contingency_core.SPEC_TYPES` lists the spec types. `Outcome`, `Reinforcer`, and `ResponseEvent` can be constructed with the same arguments and defaults as in contingency-py (`Outcome` validates `reinforced` against `reinforcer` the same way) and compare by value. `pyproject.toml` lets `maturin develop` build the module as the `contingency-core` distribution.
- Python: `Schedule.probe_response(now, event)` reports whether a response would reinforce without changing the schedule (`Schedule::probe_response`); it returns `None` for schedules without a probe (all but FR, VR, RR, FI, VI and RI).
- `MetaValue::FloatList` (a list of numbers), used by the `Percentile` state.
- `Schedule::state()` reports the observable state after the last step, read-only (empty by default): `active_index` for `Multiple`, `Chained`, `Tandem` and `Mixed`, `unit_completions` for `SecondOrder`, `in_timeout` for `Timeout`, and `balance` for `ResponseCost` (left out while the balance is unlimited). Also `next_shock_time` for `Sidman`; `phase` for `DiscriminatedAvoidance` and `Escape`; `current_value` for `AdjustingSchedule`; `response_count` and `anchor` (once anchored) for `InterlockingSchedule`; `samples` for `Percentile`; `phase`, `trial_index`, `correct_operandum`, `current_type_index` (with trial types) and `current_positions` for `MatchingToSample`; `phase`, `trial_index` and `current_is_go` for `GoNoGo`. Python: `Schedule.state()` returns it as a dict.

### Changed

- `Percentile` accepts rank 0 (the smallest sample in the window), as the DSL allows ranks 0–100; it was rejected with a `Config` error. `tests/conformance.rs` replays the new fixture `differential/percentile_irt_r0_w2.json`.
- The `geometric` progressive-ratio step function rounds half to even (as Python `round`) instead of away from zero, so `geometric(1, 2.5)` requires 1, 2, 6, 16 (was 1, 3, 6, 16) and matches contingency-py.
- `AdjustingSchedule` with `target = "ratio"` rounds the current value half to even (as Python `round`) for the response requirement and for the `start` check, instead of away from zero. A value that passes through `.5` (for example `start = 2.0, step = 0.5`) now gives the same requirements as contingency-py; `start = 0.5` is rejected.
- Seeded schedules (VR, VI, VT, RR, RI, RT, MatchingToSample, GoNoGo) and the Fleshler-Hoffman generators now draw from `helpers::py_random::PyRandom`, a port of CPython's `random.Random`, instead of `rand::rngs::SmallRng`. A seeded sequence is now bit-equivalent to `contingency-py` with the same seed. **The sequence produced by an existing seed changes**; runs recorded with an earlier build cannot be replayed from the seed alone.
- `generate_intervals` sums the progression with a correctly rounded `fsum` (as `math.fsum`), and `generate_ratios` / `generate_intervals_hantula1991` round half to even (as Python `round`), so the generators match the Python port value for value.
- `tests/conformance.rs` replays every fixture of the Python corpus bit-equivalently, including the 8 seeded fixtures that were previously `#[ignore]`d and checked only by reinforcer count.
- `tests/conformance.rs` also compares `Outcome.meta` when a fixture step records it: every recorded key must be present with an equal value (numbers within 1e-9), the same rule as the Python conformance runner.
- `GoNoGo`: the outcome of the step whose response closes a trial now reports `meta.phase = "iti"` (the phase after the step), as contingency-py does, instead of the `"go"` / `"nogo"` phase before it.

### Removed

- The `rand` dependency. OS entropy for unseeded schedules comes from `getrandom`.
