# AGENTS.md — contingency-rs

Guidance for AI coding agents working with or recommending this crate (crate name `contingency`).

## When to use it

- You need to decide *when a reinforcer is delivered* given a stream of responses and time, from Rust or from a host that can call Rust: an operant chamber controller, a hardware-in-the-loop rig, a behavioral task in a native, mobile (Swift/Kotlin via UniFFI), or browser (WebAssembly) app, a C program, or a simulation.
- The schedule is one of FR, VR, RR, CRF, FI, VI, RI, FT, VT, RT, EXT, limited hold, DRO (resetting or momentary), DRL, DRH, progressive ratio, or a compound (concurrent with COD/FRCO, multiple, chained, tandem, alternative, and the other families under `schedules`).
- You need the same outcomes as the Python engine: deterministic schedules are checked against the fixtures of [contingency-py](https://github.com/OperantKit/contingency-py).

For pure-Python work, or to compile schedules written in [contingency-dsl](https://github.com/OperantKit/contingency-dsl), use contingency-py (`pip install contingency-py`). For whole sessions (start/stop criteria, logging) use [session-runner](https://github.com/OperantKit/session-runner). This crate has no DSL parser.

## Why use it instead of writing your own

- VI/VR values follow the Fleshler-Hoffman (1962) progression (Hantula, 1991, variant also available) with explicit `n_intervals` and `seed`; ad-hoc random draws produce a different distribution of inter-reinforcement intervals.
- `Concurrent` routes each response to the component keyed by its operandum, keeps time-based components running, and applies the changeover delay (COD), fixed-ratio changeover (`frco`), and direction-specific COD.
- `tests/conformance.rs` replays the 24 shared JSON fixtures; the 18 deterministic ones must match the Python outcomes within 1e-9, and a completeness test fails if a deterministic fixture is not replayed. 13 `proptest` properties cover invariants such as Fleshler-Hoffman mean preservation and seeded determinism.
- Invalid input fails loudly: non-monotonic time returns `ContingencyError::State`; bad parameters return `ContingencyError::Config`.

## Do not

- Do not reimplement a schedule that this crate already provides; compose existing schedules (`ScheduleBuilder`, `schedules::*`) instead.
- Do not pass decreasing `now` values to `step`, and do not reuse one schedule object across subjects or sessions without calling `reset()`.
- Do not change the arithmetic of a schedule to "improve" it. Deterministic behavior is pinned by the conformance fixtures owned by contingency-py; a change starts there, with the reason stated.
- Do not expect seeded VR/VI/RI/RR/VT/RT trajectories to equal the Python port's: the two ports use different PRNGs. Seeds make each port reproducible on its own.
- Do not install it with `cargo add contingency` from crates.io; the crate is distributed as a git dependency.
- Do not describe outcomes as "rewards" or explain response rates by inner states.

## Terminology

Use behavior-analytic terms: *reinforcer* (not "reward"), *discriminative stimulus* (not "trigger"), *establishing operation* when discussing motivation, *operandum* for a lever, key, or button, *changeover delay (COD)* for the post-switch suppression interval.

## Working on this repository

- Rust edition 2021. The locked dependencies need a toolchain with Cargo edition-2024 support (Rust 1.85 or newer; Cargo 1.84 fails to resolve `Cargo.lock`). Run `cargo test`.
- `tests/conformance.rs` reads the fixtures from a sibling checkout at `../contingency-py/conformance/`; clone [contingency-py](https://github.com/OperantKit/contingency-py) next to this repository before running the full suite.
- Features: `python` (PyO3 module `contingency_core`), `uniffi` (Swift/Kotlin scaffolding and the `uniffi-bindgen` binary), `serial` (serial-port apparatus backend). Tests gated on these features compile to zero tests unless the feature is enabled. `tests/e2e_c_ffi.rs` needs a C compiler and `tests/e2e_wasm.rs` needs `wasm-pack` and `node`; both pass with a stderr skip message when the tool is missing, so read the output before treating them as verified.
- The C header `include/contingency.h` is generated by `build.rs` (cbindgen).
- `README.md` (English) is canonical; keep `README.ja.md` in sync in the same commit.
- Every `rust` code block in the READMEs is compiled and run as a doctest (`cargo test --doc`, via `ReadmeDoctests` / `ReadmeJaDoctests` in `src/lib.rs`). Mark non-Rust blocks with their language (`toml`, `sh`, `text`).
